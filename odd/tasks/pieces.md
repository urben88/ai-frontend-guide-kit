# pieces

Objective: a shared library of reusable pieces (micro to large components with versions and variants) that the design flow always reuses, polishes and records automatically, indexed with SQLite + FTS5 (the same technology Engram uses) and content hashes so it stays fast as it grows.
Branch: `feat/pieces` (from `main`) · Delivery: ask-on-risk, work-unit commits; push and PR are the user's decision · Runner: `node --test` (`npm test`), full check `npm run verify` (it rewrites the date in `catalog/explorer.html`; restore that file when nothing else changed).

## Specs

- **S1 — Lego pieces, easy for an agent to read, creative.** "quiero que sea totalmente optimizado para que la lectura de una gente sea lo más sencillo y fácil posible para construir ese Lego y que sea más creativo. Al final quiero darle creatividad con los bloques que tengo."
  Acceptance: a piece is a real component with variants as props, never a copy per variant. Levels: `micro`, `small`, `medium`, `large`. Each piece has one short `piece.json` (name, level, summary, variants, contexts such as size/margin/page type, `composedOf` pieces, likes, license, latest version) and its versioned source files. `pieces list` and `pieces show <name>` print a compact, agent-readable view (latest state first).
- **S2 — Reuse automatically, give the site a personality.** "cada vez que vaya generando cosas, automáticamente vaya usando esos micro componentes o componentes más pequeños con diferentes tipos y versiones para poder ir creando y adaptando una personalidad a la página web, para que no lo empiece de cero."
  Acceptance: the library is shared across projects (user decision, L4). Default location `~/.ai-frontend-guide-kit/pieces/`, override with `AI_FRONTEND_PIECES` or `--lib`. Each project keeps only its personality and its usage in `ai-frontend-output/pieces.json` (which pieces, version and variant it uses, plus project-level settings such as spacing or image weight). The project's tokens stay in `DESIGN.md`.
- **S3 — Reuse to the maximum; create new only as the last conclusion.** "Lo que quiero es reutilizar al máximo, cuando creo una cosa que lo reutilice en las próximas y por tanto ir puliendo ese mismo componente si lo uso en otras páginas web y le digo ¡Ostras! Aquí quiero ponerle más imagen, quiero más espaciado, pues al final voy puliendo esos componentes porque los voy reutilizando siempre que puedo. Hay un componente que no exista, pero ahí tiene que buscarlo muy bien y llega a la conclusión, la última conclusión de que no exista, entonces sabéis cuando se crea otro componente nuevo."
  Acceptance: `pieces find <need>` searches in this order and prints the decision: own piece > new variant of an own piece > kit catalog (`ui-map have` / catalog search) > new piece. `pieces add` refuses a new piece when `find` was not run for that need in this project, or when an exact or close match (name or structural hash) exists, unless `--new --reason "..."` explains why none fits. A polish request ("más espaciado") becomes a new version or variant of the same piece, not a new piece. Extract a piece only when it repeats, the user likes it, or it makes sense on its own.
- **S4 — Save versions, use and feedback automatically.** "O si yo le pido versionado, mientras estoy creando diseños, que eso lo vaya guardando. Los que vaya a usar y los que de feedback, de que me gustan o que estoy haciendo cosas. Quiero que se guarden automáticamente sin yo tener que nombrarlo."
  Acceptance: commands `pieces version`, `pieces use`, `pieces like`, `pieces dislike`, `pieces note` append to the library's `history.jsonl` (append-only, with project, piece, version, time). The routing block, `AGENTS.md` and the skill tell the agent to record use, versions and feedback on its own whenever the user reacts, without the user asking.
- **S5 — Injected in the flow.** "Que él en su flujo inyecte a la gente en el flujo cuando estoy creando frontend de que tiene que tener este watch."
  Acceptance: the `compose` and `iterate` steps of `tools/flow.mjs` list `pieces find` as their first tool; `flow done compose|iterate` refuses while a `build` decision in `selections.jsonl` has no registered piece. `memory add --decision build` refuses unless `pieces find` ran for that need.
- **S6 — Indexed like Engram, with history and taste.** "Que tenga un tipo de indexación como usa Engram, es decir, la misma tecnología que usa Engram, pero quiero que lo añadas en este apartado para que a la gente se le resulte muy fácil saber el último estado de los componentes, el diseño que yo quiero, la indexación de estos componentes, personalizar un poco cómo quiero escoger las cosas para que tenga un cierto historial"
  Acceptance: files stay the source of truth; `index.db` (SQLite + FTS5 through the built-in `node:sqlite`, no new dependency) is rebuilt from them with `pieces index` and refreshed automatically by every mutating command. Searches answer: latest state of a piece, its history, what the user likes, and whether something already exists. Ranking puts liked and most-used pieces first and dislikes last. When `node:sqlite` is unavailable (Node older than 22.13), every command still works by scanning the files and says so once; `engines` stays `>=18`.
- **S7 — Hashes so it scales.** "quiero que la indexación tenga, por ejemplo, algoritmos de hash para poder simplificar esto para cuando vaya creciendo mucho."
  Acceptance: each version stores the SHA-256 of its content; an identical version is never stored twice (the command says which version it equals). Re-indexing only processes pieces whose hash changed. A structural hash (source with names, strings and whitespace normalized away) flags near-duplicates in `add` and `find`.
