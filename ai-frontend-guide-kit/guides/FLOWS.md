# Flows of the AI Frontend Guide kit

Generated by `node ai-frontend-guide-kit/tools/flow.mjs list`; do not edit by hand. Every design conversation declares one route with `node ai-frontend-guide-kit/tools/flow.mjs start <route>` and follows its steps in order: `node ai-frontend-guide-kit/tools/flow.mjs next` prints the whole instruction of the current micro-step (goal, exact commands, template, done criteria), already resolved for what this project has installed, `node ai-frontend-guide-kit/tools/flow.mjs scaffold` writes the skeleton of the file the step asks for, and `node ai-frontend-guide-kit/tools/flow.mjs done <step>` refuses a skipped step, a missing artifact or a file whose required sections are empty or still hold a template token. The steps closed with evidence (`polish`, `iterate`, `redesign`, `visual-feedback`) also need their report: `node ai-frontend-guide-kit/tools/flow.mjs report <step>` writes the checklist. `next` names only the skills this project has installed; the rules of `guides/08-PHILOSOPHY.md` cover the rest.

The user decides, the agent does not. The parts that are the user's choice (`direction.questions`, `direction.references`, `direction.choose`, `ux.product` when PRODUCT.md must be asked, `compose.decide`, and the Storybook question of `board`) end `next` with a STOP block: the agent shows the options, waits, and closes the part with `node ai-frontend-guide-kit/tools/flow.mjs done <step>.<part> --answer "<the answer of the user>"`; the answer stays in `flow-state.json`. `next` also lists the kit tools that fit the micro-step, each with its command, what it gives and its cost, so the user picks which to use (`--tools <ids>` on `done` records the pick). `done` prints a summary for the user (what was done, tools, files, next step) and `node ai-frontend-guide-kit/tools/flow.mjs report` writes the whole route to `ai-frontend-output/FLOW-REPORT.md`. `compose` also refuses while a catalog component decided reuse or adapt is not imported by any page or component.

## Routes

| Route | When | Steps |
|---|---|---|
| `new` | New frontend or major build (phases 1 → 2 → 3) | intake → direction → ux → tokens → compose → board → polish |
| `direction` | Direction only, no UI | intake → direction |
| `ux` | UX only or UX redesign, no UI work | intake → ux |
| `iterate` | Small change or custom component | intake → iterate → polish |
| `polish` | Polish only or visual QA | intake → polish |
| `redesign` | Visual redesign of an existing screen | intake → redesign → polish |
| `visual-feedback` | Point-and-change in the browser (React) | intake → visual-feedback |
| `architecture` | Folder map, or FSD structure when asked | intake → architecture |

## Parts of the large steps

Closed in order with `node ai-frontend-guide-kit/tools/flow.mjs done <step>.<part>`; a skipped part is refused and the last part closes the step. `done <step>` still closes a whole step at once.

| Step | # | Part | What it does |
|---|---|---|---|
| `direction` | 1 | `direction.questions` | ask the user about the product, the audience and the goal |
| `direction` | 2 | `direction.classify` | choose the archetype, the philosophy and the navigation model |
| `direction` | 3 | `direction.journey` | write the journey and the information architecture |
| `direction` | 4 | `direction.references` | look at real examples with the user |
| `direction` | 5 | `direction.directions` | propose three directions that differ in structure |
| `direction` | 6 | `direction.choose` | the user chooses; write the visual brief |
| `ux` | 1 | `ux.product` | anchor the product |
| `ux` | 2 | `ux.spec` | write the screens, flows and states |
| `ux` | 3 | `ux.map` | draw the screen map |
| `compose` | 1 | `compose.inventory` | list what each screen needs |
| `compose` | 2 | `compose.find` | search before creating anything |
| `compose` | 3 | `compose.decide` | decide reuse, adapt or build, install and record |
| `compose` | 4 | `compose.adapt` | make every piece look like this product, and register it |
